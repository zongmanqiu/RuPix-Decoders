# 历史策略（每 DLL 一份）

## 粒度

- 只给**四个发布 DLL** 写历史：`workspace/decoders/{common,modern,raw,pro}/HISTORY.md`。
- 22 个单库不单独写历史：它们不是独立发布物，历史由所属档的记录覆盖；
  单库 README 只写当前实现与限制。
- ABI 版本史不放在这里，放 `解码器开发规范.md` §九。档历史只写“DLL 对用户/宿主可见的变化”。

## 版本号与日期

- `HISTORY.md` 的标题版本 = `workspace/decoders/<id>/Cargo.toml` 的 `[package] version`。
- 标题日期 = 该版本发布日；必须与 `decoders.json` 的 `released` 一致。
- ABI = `abi/src/lib.rs` 的 `IV_ABI_VERSION`（当前 6）。
- 版本号只在 `Cargo.toml` 改；`HISTORY.md` 跟着加条目，不复制版本号到别处。

## 发布状态不写进历史

`HISTORY.md` **只记录已确定的版本事实**，不记录发布操作进度：

- 不写 `**状态**`；
- 不写“待上传”“发布包已生成”“等待 Gitee/GitHub”；
- 不写 `release tag`、Gitee/GitHub URL、资产文件名或 ZIP 是否已生成；
- 不写“未发布”条目。未发布版本的改动并入下一次正式发布条目，不单独留在历史里。

发布是否完成、ZIP 是否生成、地址是否可下载，唯一真源是 `decoders.json`。
`HISTORY.md` 的日期是**发布日**，不是上传开始日；发布由维护者手动操作，不改变代码事实。

## 条目格式

```markdown
# <id> 历史

> 只记 DLL 对外可见的变化。ABI 版本史见 `解码器开发规范.md` §九。

## 0.2.0 — 2026-10-27 — abi 5

- **变更**：新格式 / 换库 / 修缺陷 / 性能 / 兼容性
- **影响**：一句话说清用户或宿主感知到什么
- **后缀**：33（`foo` `bar` `baz`）
- **能力位**：`CAP_*` 变化；新增/移除可选导出
- **限制**：新增或解除的已知空白
- **证据**：测试名 / golden / 可复现命令
- **升级建议**：必须升 / 可选升 / 仅修 bug
```

规则：

- 最新版本在最上面。
- 一版一条；同版本的多项改动合并成一组 bullet，不按提交拆。
- 纯内部重构最多一行；没有对外影响的格式化/注释不记。
- 不写 `.temp` 临时台账当唯一证据；证据要能在仓库里复跑。
- 不写真实用户名、本机绝对路径、密钥。

## 什么算对外可见

记：

- 认领后缀增删；
- 能力位、可选导出（`iv_render_raw` / `iv_caps`）变化；
- 像素结果、方向、ICC、多帧/多页语义变化；
- 明确的性能档位变化（有配对读数）；
- 体积策略变化（合并/拆分/换库）；
- 兼容性：最低宿主版本、ABI、已知会拒载的输入。

不记：

- 纯函数重命名、模块搬家、注释；
- 测试内部重构；
- 没有读数的“感觉更快”；
- 宿主侧的 m 号（可以作为上下文带一句，不做标题）。

## 版本怎么升

| 变化 | 建议 |
|---|---|
| 新增后缀/成员、能力位增加 | minor |
| 修缺陷、性能、内部换库但行为不变 | patch |
| 移除后缀/成员、像素语义变化、需要用户注意的兼容性 | 至少 minor，必要时 major |
| ABI 变更 | 另走 `解码器开发规范.md` §九，必须用户拍板 |

版本号由维护者定；`HISTORY.md` 不替 `Cargo.toml` 做主。

## 门禁

`tools/check_history.py` 校验：

- 四份 `HISTORY.md` 存在；
- 最新标题的版本 = `Cargo.toml` 版本；
- 标题格式必须是 `## <version> — <YYYY-MM-DD> — abi <N>`；不接受 `未发布` 标题；
- 最新标题日期 = `decoders.json.released`（已发布时）；日期不能在未来；
- 版本不重复；
- 禁止出现 `- **状态**`、`待上传`、`发布包已生成`、`等待 Gitee/GitHub`、`未发布`、
  `release tag`、Gitee/GitHub URL。

它已由 `build.ps1` 在编译前执行；`violations: 0` 才算过。
