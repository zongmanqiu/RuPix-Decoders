# 矢量解码器开发规则（ABI v6）

日期：2026-10-28。本文是解码器侧的**开发清单**；契约全文仍以 `abi/src/lib.rs` 和
`../解码器开发规范.md` §十六为准。宿主侧已经完成，解码器**不需要改宿主**。

## 1. 先记住三条总规则

1. **矢量格式一律由解码器自渲染**（`DllSelf`）。宿主只内置 `svg/svgz`；
   不再提供“解码器交出 SVG、宿主 resvg 渲染”的路线。
2. **放大必须重新光栅化**：不许“整幅渲染后插值放大”。区域请求就是给这条用的。
3. **字体是硬要求**：没有原字体也要用兜底字体把文字画出来；不许丢字、空字、留白或崩。

## 2. ABI 状态

- `IV_ABI_VERSION = 6`；宿主收载区间 **5 ≤ abi ≤ 6**。v5 老 DLL 照常加载，不能因为
  没有区域渲染而拒载。
- v6 是加法式：`iv_render_region` 是**新可选导出**，`IvRegionReq` 是**新结构体**
  （40 B），`CAP_REGION = 1<<6` 是**新能力位**；既有签名/结构体不改。
- `iv_export_svg` 只是**冻结保留的历史符号**：宿主已不再调用它，新的矢量解码器
  不要再实现“导出 SVG 给宿主”的路线。`CAP_VECTOR` 现在的含义是“提供矢量解码”，
  不再与 `iv_export_svg` 绑定。
- 合并档（如 `pro`）要把成员的 `iv_render_region` 转发出去，并声明 `CAP_REGION`；
  单库用 `export_region!` / `export_region_impl`。

## 3. 区域渲染契约

```c
typedef struct IvRegionReq {
    float    x, y;        /* 文档自然像素坐标 */
    float    w, h;        /* 区域尺寸（文档自然像素） */
    uint32_t target_w;    /* 输出画布宽；0 = 与 w 同值 */
    uint32_t target_h;    /* 输出画布高；0 = 与 h 同值 */
    uint32_t budget_bytes;/* 0 = 不限；超限 ERR_TOO_LARGE */
    uint32_t flags;       /* 矢量路线恒 0 */
    uint32_t frame_index;
    uint32_t page_index;
} IvRegionReq;
```

必须遵守：

- **坐标系**：`x/y/w/h` 是文档自然像素，和 `iv_render` 查询回报的
  `actual_w/actual_h` 同一坐标系。内部用 pt/1/72 英寸/device unit 的地方自己换算。
- **画布**：`target_w/target_h` 是本次输出画布；密度 = `target_w / w`。把区域
  `(x,y,w,h)` **直接光栅化**到目标画布，不是先整幅渲染再缩放。
- **两阶段**：`out == NULL` 只查询并填 `IvRenderOut`，**不写像素**；第二次按
  `bytes_needed` 写入。`out_cap < bytes_needed` → `ERR_BUFFER_TOO_SMALL`，不写一字节。
- **等比缩进**：区域比例和画布比例不一致时等比缩进；允许
  `actual_w/actual_h` 与 `target_*` 不同，不能拉伸变形。
- **越界透明**：超出文档范围的区域输出 alpha=0，不要报错。
- **预算**：超过 `budget_bytes` 或解码器自设上限 → `ERR_TOO_LARGE`，不崩、不越界写。
- **缓存**：同一份字节会被连续用不同区域请求（每次平移/缩放都会来一次），
  解析结果必须在进程内缓存；WMF 参考实现用容量 4 的 SVG 场景缓存。
- **错误口径**：`ERR_UNRECOGNIZED` = 不是本格式；`ERR_CORRUPT` = 文档损坏；
  `ERR_TOO_LARGE` = 超限；两阶段/缓冲错误按上面。失败原因写 `iv_last_error`。
- **可选性**：没有 `iv_render_region` 也能发布；宿主探测不到符号就不发区域请求，
  自动落回整幅路线（放大不锐，但不会拿错内容）。**矢量解码器应当实现它**，但不作为
  接档的强制门槛。

## 4. 自述与能力位

- `iv_metadata` 的 `vector_exts` 键列出本解码器认领的矢量后缀（分号分隔，小写）；
  合并档尤其需要，因为成员级矢量能力不能塞进 DLL 级 `is_vector` 单值。
- 自渲染的矢量解码器写 `vector_render=target`，告诉宿主它按 target 自己渲染。
- 只有真的实现了 `iv_render_region` 才声明 `CAP_REGION`；**不许**只写能力位不实现导出。
  宿主对 `CAP_REGION` 按“符号在不在”判定，凭空声明不会得到能力。
- `probe` 仍按魔数/内容认领；`ext == NULL` 时不能靠后缀猜格式。区域请求的 `ext`
  也要按同一认领闸检查。

## 5. 字体（硬要求）

- 优先级：**文档内嵌字体 → 文档指定的系统字体 → 任意可用兜底字体**。
- 找不到原字体时，**必须**用兜底字体渲染；不许丢字、空字、留白或崩溃。
- 用了兜底字体时，在 `iv_last_error` 写一句可读说明；宿主会在渲染成功后读取它，
  写成 `[vector-note] decoder=… file=… note=…`。这是“字体被换过”的唯一可观测痕迹。
- 兜底字体在不同机器上可能不同 ⇒ 同一文件跨机像素可能不一致。这是
  `.plan/m153` 例外登记簿 **E2** 的已接受例外，不要再为“逐字节跨机一致”牺牲文字。

## 6. 新矢量格式的默认策略

不要每遇到一个后缀就重新拍板。默认规则：

> **能解析 + 能认领 + 能按目标尺寸渲染 + 能区域渲染 + 错误口径正确 + 不越界不崩
> ⇒ 默认接。**

例外只登记在 `.plan/m153` 的例外登记簿，目前的口径：

- **E1**：PDF 不做。
- **E2**：字体兜底例外，接受跨机像素差异（见 §5）。
- **E3**：PS / EPS / AI 默认按“能解析就接”处理；解析质量不过准入清单时再登记例外。
- **E4**：`pro` 的 WMF 归属按格式分类规划处理；WMF 目前仍是 `pro` 的参考矢量实现，
  未来目标 `doc`，不要把它当成“矢量栈必须迁走”的前置条件。

## 7. 验收清单（必须全部过）

1. `iv_probe` 认领样本；`iv_render` 查询自然尺寸 > 0。
2. 同一文件请求两块不同区域或不同 target，画布跟着变，且**不是同一张位图放大**。
   推荐对照：区域重渲硬边 vs 同区域双线性插值；插值硬边会归零。
3. 区域比例与画布比例不同时，等比缩进不拉伸。
4. 区域越界部分透明，不报错、不写垃圾像素。
5. `budget_bytes` 超限返回 `ERR_TOO_LARGE`，不崩、不越界。
6. 同机 1080p 视口区域渲染 < 50 ms、4K < 150 ms（各 20 次取中位数）。
7. 字体缺失时仍渲染文字，并在 `iv_last_error` 留下兜底说明。

## 8. 第三方矢量栈与边界

- 宿主**不含** librevenge / libfreehand / cairo / fontconfig / harfbuzz；通用矢量
  解析和光栅化在解码器 DLL 侧。当前 `.3rd` 也没有这些源，接入前必须按仓库规则放到
  `.3rd/<name>-<ver>/` 并登记补丁/许可证。
- `pro-wmf` 是现有骨架参考：WMF → SVG → resvg，区域重渲、越界透明、字体兜底、
  进程内场景缓存；新矢量成员可以照这个形状做，但不要把 WMF 特例写进通用规则。
- 宿主只负责通道、区域判据、调用编排、预算和降级；**不需要也不应该改宿主**。
- `CAP_REGION`/区域通道缺席时，宿主降级为整幅渲染；不要为了避免降级而谎报能力。

## 9. 发布与 ABI 门禁

- 新 DLL 实现 `iv_render_region` 后按 ABI v6 发布；`decoders.json` 的 `abi` 必须是
  **实际 DLL 的 abi**，不能提前写成 6。
- `check_history` 报旧 HISTORY 的 `abi 5` 与新契约代次不一致，是提示全体重编重发，
  **不要伪造历史**；发布时逐档重编、重打 ZIP、再更新 `decoders.json`。
- 未实现区域渲染的 v5 DLL 仍可工作；它们只是没有无损放大通道。
