# 第三方补丁登记（`patches/`）

本目录登记**对仓库外第三方源码所做的补丁**——被补的源码本身不进仓库（放在工作区
`../.3rd/<name>-<version>/`，见那里的 `README.md`），进仓库的是**能重建它的最小材料**：
一份对上游原文的补丁 + 一份人读说明 + 一份机器读的登记。

| 目录 | 上游 | 版本 | 补丁用在 | 补丁 |
|---|---|---|---|---|
| `emfsdk-0.2.0/` | `KaiserY/emfsdk`（crates.io `emfsdk`） | 0.2.0 | `doc` 档的 `doc-emf`（EMF/EMZ 文本） | E01 |

## 每个目录必须有什么

| 文件 | 作用 | 谁读 |
|---|---|---|
| `manifest.json` | 基线版本 / `.crate` 校验和 / 补丁清单 / 补丁后文件哈希 / 上游核对日期 | `tools/check_patches.py`（构建门禁） |
| `README.md` | 为什么改、改了哪里、怎么重放、上游怎么核对 | 人 |
| `*.patch` | 对**上游原文**的统一 diff（`a/` `b/` 前缀，可 `git apply`） | 重放补丁的人 / 门禁核哈希 |

判定标准只有一条：**上游原文 + 本目录全部补丁 = 构建时用的那份副本，逐字节一致**。
门禁无法凭空验证前半句（仓库里没有上游原文），所以它核两件可离线核的事：补丁后像的
git blob 哈希 == 副本文件的哈希，以及补丁后文件的 sha256 == `manifest.json` 里记的值。

## 这是「跟随上游」的补丁，不是分叉

- **基线永远取上游的同一个版本**：补丁只叠加在 `emfsdk 0.2.0` 原文上，不携带任何上游
  之外的改动；上游一旦升级，我们重放补丁，而不是把旧文件整份搬过去。
- **每 90 天必须去上游核对一次**：`manifest.json` 的 `upstream_check.checked_at` 过期后
  `tools/check_patches.py` 直接判红，构建流水线停下——核对完（无论上游有没有变）把日期改成
  核对当天。这条是刻意的：「上游发了新版我们不知道」不会显形，只能靠日期逼一次人工动作。
- **升级流程写在各目录 README 的「上游核对 / 升级」一节**，与工作区 `.3rd` 的 `SOURCE.md`
  保持同一份事实（两处都改，不许只改一处）。
